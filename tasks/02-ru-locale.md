# 02. Русская локаль интерфейса, по умолчанию

## Зачем

NzrAiWiki должен открываться на русском у любого нового посетителя. Сейчас
локали `ru` нет, по умолчанию стоит `en` (`web/i18n/config.ts`).

Форк продолжает подтягивать апстрим, а там регулярно добавляют новые ключи в
`en/*.json`. Новый ключ, которого нет в `ru`, не должен ломать страницу или
показывать голый ключ. Он должен показаться по-английски, а скрипт проверки должен
его найти.

## Что сделать

1. **`web/i18n/config.ts`:**
   - добавить `"ru"` в `uiLocales`;
   - в `uiLocaleNames` добавить `ru: "Русский"`;
   - `defaultUiLocale = "ru"`;
   - `resolveUiLocaleFromWikiLanguage("ru")` должен вернуть `"ru"`: проверить, что
     сработает общая ветка, и не дописывать спецслучай без нужды.

   `defaultWikiLanguage` и `wikiLanguageCodes` не трогать.
2. **Резерв на английский.** В `web/i18n/request.ts` для любой локали, кроме `en`,
   глубоко слить сообщения локали поверх `en`: отсутствующий ключ берётся из `en`.
   Делать в одном месте, `loadMessages`, без новой зависимости: маленькая функция
   `deepMerge` рядом. Поведение для существующих локалей не меняется, у них полный
   набор ключей.
3. **Переводы.** Создать `web/i18n/messages/ru/` с переводом **всех** файлов из
   `web/i18n/messages/en/`, **кроме `admin.json`**: его переводит задача 03
   параллельно, файл не создавать и не трогать. Источник — `en`.
   - Структура ключей точно как в `en`, переводятся только значения.
   - Плейсхолдеры `{name}`, `{count}` и т.п. сохранить буква в букву. Где в значении
     есть число (`{count} files`), можно и нужно использовать ICU-плюрал
     `{count, plural, one {# файл} few {# файла} many {# файлов} other {# файла}}`,
     next-intl его поддерживает.
   - Название продукта — **NzrAiWiki** (не OpenDeepWiki и не DeepWiki), даже если в
     `en` пока стоит старое: ребрендинг `en` делается параллельно в задаче 01.
   - Спонсорские тексты routin.ai в `common.json` перевести как есть: баннер
     выключается в задаче 01.
   - Тон: обычный интерфейсный русский, на «вы», короткие кнопки
     («Сохранить», «Отмена», не «Нажмите, чтобы сохранить»). Без канцелярита.
   - Глоссарий:

     | en | ru |
     |---|---|
     | repository | репозиторий |
     | wiki | вики |
     | catalog / table of contents | оглавление |
     | branch | ветка |
     | provider | провайдер |
     | model | модель |
     | token | токен |
     | prompt | промпт |
     | mind map | карта связей |
     | bookmark | закладка |
     | subscribe | подписаться |
     | MCP, API, URL, OAuth, GitHub | не переводить |
4. **Скрипт проверки** `web/scripts/check-i18n-ru.mjs` (Node, без зависимостей):
   - сравнивает ключи `en/*.json` и `ru/*.json`;
   - печатает отсутствующие в `ru` ключи, лишние ключи и плейсхолдеры, которые не
     совпадают (`{x}` есть в `en`, но нет в `ru`; ICU-плюрал засчитывается как
     наличие переменной);
   - код выхода 1, если что-то нашлось.

   Добавить в `web/package.json` скрипт `"i18n:check-ru": "node scripts/check-i18n-ru.mjs"`.

## Чего не делать

- Не трогать `web/i18n/messages/ru/admin.json`: это задача 03.
- Не трогать брендовые правки задачи 01: `web/app/sidebar.tsx`, `web/lib/*`,
  компоненты, словари других локалей, LICENSE, README.
- Не трогать `middleware.ts`, если без этого всё работает. Там приоритет такой:
  `?lang=` > cookie > `defaultUiLocale`, детекции по `Accept-Language` нет, так что
  смены дефолта достаточно. Если нашёл иное — опиши в отчёте.
- Не переводить захардкоженные строки в компонентах: это отдельная задача позже.

## Ворота (выполнить и привести вывод в отчёте)

- `cd web && npx tsc --noEmit` — без новых ошибок относительно `main`.
- `cd web && npm run lint` — без новых ошибок.
- `cd web && npx vitest run` — как на `main`. Тест, который закрепляет старый
  дефолт `en`, обновить и объяснить, почему.
- `npm run i18n:check-ru` — единственные находки: ключи `admin.*`, потому что файла
  ещё нет.
- Проверка резерва: временно удалить из `ru/common.json` один ключ, убедиться
  (тестом или выводом `loadMessages`), что подставляется английское значение, и вернуть
  ключ. Лучше оформить это постоянным vitest-тестом на `deepMerge`.

`node_modules` может не быть — тогда `npm ci`. Коммитить не надо.
