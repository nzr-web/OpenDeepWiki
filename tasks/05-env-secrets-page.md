# 05. Обязательная страница «Переменные окружения и секреты» в каждой вики

## Зачем

Владелец хочет, чтобы в **каждой** сгенерированной вики была страница-справочник:
все переменные окружения и все ожидаемые секреты репозитория, для каждой — что она
значит и где используется.

Сейчас такой страницы может не быть: оглавление целиком придумывает LLM. Для вики
самого проекта похожая страница появилась (`deployment-operations.configuration`),
для `service-graph` — нет. На просьбу в промпте полагаться нельзя: локальная модель
её иногда пропустит.

Владелец подтвердил, что в его коде настоящих значений секретов нет, только
заглушки. Поэтому вычистки текста нет, а значения секретов просто не выводятся.

## Принятые решения (не пересматривать)

1. **Пункт гарантирует код, а не модель.** После того как модель записала
   оглавление, сервис добавляет пункт с фиксированным путём
   `environment-and-secrets`, если его нет.
2. **Полноту даёт детерминированный сканер, а не модель.** Сканер по шаблонам
   находит имена и места. Его результат и требования к странице идут агенту
   **отдельным сообщением, которое целиком заменяет** обычное сообщение генерации
   документа. Ничего не дописывается, чтобы модель не получала противоречивых
   требований.
3. **Полнота страницы гарантируется кодом.** После генерации детерминированный
   проход дописывает на страницу имена из сканера, которых модель не упомянула.
4. **Значения секретов не выводятся.** Сканер не отдаёт их нигде. Инструкция
   запрещает модели их писать.
5. **Апстримный код меняется минимально.** Всё новое — в новых файлах. В
   `WikiGenerator.cs` допускается только следующее:
   - вызов сервиса обязательного пункта в `GenerateCatalogAsync`;
   - в `GenerateDocumentContentAsync` выбор сообщения и бюджетов по пути через
     новые методы;
   - вызов прохода полноты после успешной генерации этой страницы.

   Промпты в `prompts/` не трогать. Инструкции для страницы — константа или
   ресурс в новом классе, не новый файл промпта.
6. **Принятые ограничения, сознательно:**
   - инкрементальное обновление может отредактировать страницу общим промптом,
     и проход полноты к нему не применяется;
   - перевод на другие языки переводит страницу как обычную;
   - если модель сама создала похожую страницу под другим путём, дубли не
     убираем;
   - ни одно из этого не делать.

## Что сделать

### 1. Обязательный пункт оглавления

Новый сервис (например `MandatoryCatalogPages`). Вызывается в
`WikiGenerator.GenerateCatalogAsync` сразу после проверки `catalogItemCount == 0`.

- Через `CatalogStorage.GetCatalogJsonAsync` проверить, есть ли на любом уровне
  пункт с путём `environment-and-secrets`. Сравнение — после `Trim('/')`,
  `OrdinalIgnoreCase`.
- Нет — добавить последним пунктом верхнего уровня (`order` = максимум + 1, без
  детей) и записать через `SetCatalogAsync`.
  - Проверено ревью: при добавлении одного пункта `SetCatalogAsync` сохраняет
    `Id` и `DocFileId` существующих записей.
  - Тест это закрепляет, см. раздел «Тесты».
- Есть, но с детьми — ничего не менять, `Warning` в лог: страница не будет
  сгенерирована, потому что `DocTool` не пишет в узел с детьми.
- Заголовок по коду языка ветки, без учёта регистра:

  | коды | заголовок |
  |---|---|
  | `ru` | `Переменные окружения и секреты` |
  | `zh`, `zh-cn`, `zh-hans` | `环境变量与密钥` |
  | `zh-tw`, `zh-hant`, `zh-hk` | `環境變數與密鑰` |
  | `en` и все остальные | `Environment variables and secrets` |

- Повторный вызов пункт не дублирует.
- Любая ошибка этого шага (в том числе в `SetCatalogAsync`) пишется в лог как
  `Warning` и **не роняет** генерацию оглавления.
- Существующие вики получат пункт при следующей полной генерации или
  перегенерации. Миграции не делать.

### 2. Сканер `EnvironmentReferenceScanner`

Чистый детерминированный класс. На вход — путь к рабочей копии. **Исключений
наружу не бросает никогда.**
- Ошибка чтения файла — пропуск и `Warning` в лог с путём, без содержимого.
- Общая ошибка — пустой результат с флагом `Failed`.

Файлы разбираются **построчными регулярками**, без YAML- и JSON-парсеров: шаблоны
Helm с `{{ }}` невалидны как YAML.

**Обход:**
- пропускать каталоги `.git`, `node_modules`, `bin`, `obj`, `dist`, `build`,
  `out`, `target`, `vendor`, `.venv`, `venv`, `__pycache__`, `.next`, `coverage`;
- пропуск по имени каталога действует на любой глубине — это осознанно;
  `.github` обходится;
- пропускать файлы больше 512 КБ и бинарные (нулевой байт в первых 8 КБ);
- сортировка выдачи — `StringComparer.Ordinal` по относительному пути (прямые
  слеши), затем по номеру строки.

**Источники и шаблоны:**

| Источник | Шаблоны |
|---|---|
| C# | `Environment.GetEnvironmentVariable("X")`, `GetEnvironmentVariable("X")`, `configuration["X"]` / `_configuration["X"]` / `config["X"]`, `GetValue<…>("X")` |
| Python | `os.getenv("X")`, `os.environ["X"]`, `os.environ.get("X")`, `environ.get("X")` |
| JS/TS | `process.env.X`, `process.env["X"]`, `import.meta.env.X` |
| Go | `os.Getenv("X")`, `os.LookupEnv("X")` |
| Java/Kotlin | `System.getenv("X")`; `${X}` и `${X:default}` в `application*.yml|yaml|properties`; `@Value("${x}")` |
| compose | `${X}`, `${X:-d}`, `${X-d}` в `docker-compose*.y*ml` и `compose*.y*ml`; ключи внутри блока `environment:` в обеих формах (`- X=…` и `X: …`) |
| Dockerfile | `ENV X`, `ENV X=…`, `ARG X` в `Dockerfile*` |
| Kubernetes/Helm | `- name: X` **только внутри блока `env:`** (по отступу); `secretKeyRef` у такой записи |
| CI | `${{ secrets.X }}`, `${{ vars.X }}` в `.github/workflows/*.y*ml` |
| Примеры | `X=` в `.env.example`, `.env.sample`, `.env.template`, `*.env.example` |

**Правила отсева:**
- имя должно соответствовать `^[A-Za-z_][A-Za-z0-9_]*$`, ключ .NET — с `:`;
- `$${X}` (экранирование в compose) — пропускать;
- оболочечные `PWD`, `HOME`, `PATH`, `HOSTNAME`, `USER`, `SHELL`, `TERM`,
  `LANG` — исключать;
- `environment:` в `.github/workflows` (имя окружения деплоя) — не блок
  переменных;
- `GetSection("X")` не считать переменной вовсе;
- `${X}` в Markdown, README и shell-скриптах не искать: сканируются только
  перечисленные типы файлов.

Ключ .NET `A:B` показывать и в форме переменной `A__B`, одной записью.

**Секрет или нет** — по **токенам** имени: разбить по `_`, `-`, `:`, `.` и
границе camelCase, сравнивать без учёта регистра.
- Секрет, если есть токен из списка: `KEY`, `SECRET`, `TOKEN`, `PASSWORD`,
  `PASSWD`, `PWD`, `CREDENTIAL`, `CREDENTIALS`, `PRIVATE`, `CERT`, `DSN`, `APIKEY`.
- Секрет и тогда, когда подряд идут токены `CONNECTION`+`STRING`, `AUTH`+`TOKEN`,
  `AUTH`+`KEY`, `ACCESS`+`KEY`.
- Секрет, если имя пришло из `secrets.X` или `secretKeyRef`.
- Не секреты: имя целиком `PWD`, имя с токеном `AUTHOR` или `AUTHORITY`, а также
  имя, где после секретного токена идёт `PATH`, `FILE`, `URL`, `TTL`, `ID`,
  `HEADER`. Например, `CERT_PATH`, `TOKEN_TTL`, `KEY_VAULT_URL` — не секреты.

**Запись на имя:** `Name`, `EnvName` (если отличается), `Sources`,
`Locations` (до 5 мест `path:line`), `IsLikelySecret`, `SecretReason`,
`DefaultValue`.

`DefaultValue` — **только у не-секретов** и только из `.env.example` /
`.env.sample` / `.env.template`, `${X:-d}` / `${X:d}` / `${X-d}` или
`ENV X=d`. Из настоящих `.env`, кода и YAML-значений не брать. У секретов —
всегда `null`.

**Отрисовка для сообщения:**
- markdown-таблица (имя, секрет?, источники, по умолчанию, места);
- общий объём не больше 24 000 символов;
- что не влезло, перечисляется компактной строкой имён без мест, чтобы все
  имена дошли до модели;
- если и она не влезает — «…и ещё N».

При пустом результате — фраза, что переменные не обнаружены. При `Failed` —
пометка, что сканер не отработал.

### 3. Своё сообщение и бюджеты для страницы

Новые `internal static` методы (в новом классе), которые вызывает
`GenerateDocumentContentAsync`:

- `IsEnvironmentPage(path)` — сравнение после `Trim('/')`, `OrdinalIgnoreCase`;
- `GetDocumentBudgets(path, options)`:
  - для этой страницы — источники 12, общий лимит вызовов
    `max(20, 12 + MaxDocumentAppendOperations + 4)`;
  - для остальных — значения из опций, как сейчас;
  - найти, где создаётся `DocumentSourceToolBudget` и где задаётся
    `maxToolCallsBeforeEarlyCompletion`, и подставить оттуда;
- `BuildEnvironmentPageMessage(...)` — **полная замена** пользовательского
  сообщения для этой страницы. Сохраняет из обычного сообщения:
  - Runtime Context (репозиторий, ветка, язык, заголовок пункта);
  - File Reference Base URL с правилами ссылок;
  - правила записи через `WriteDoc` / `AppendDoc`.

  Добавляет таблицу сканера и требования к странице. В нём **нет** обычных
  требований про обязательную диаграмму и примеры кода, а бюджет назван 12.

**Требования к странице** (на языке ветки):
1. H1 — заголовок пункта.
2. Короткое вступление: откуда приложение берёт настройки, по найденным
   источникам.
3. **Таблица переменных окружения** (не секреты): имя, назначение, обязательна
   ли (только если это видно в коде — нет значения по умолчанию, проверка на
   пустоту, `required`; иначе «не установлено»), значение по умолчанию, где используется (ссылки по File Reference Base URL).
4. **Таблица секретов**: имя, что это (API-ключ к X, пароль БД Y), откуда
   ожидается (k8s Secret, CI secret, `.env`), где используется.
   **Значения не писать**, вместо них `***`.
5. Каждую переменную из таблицы сканера включить. Если назначение не
   установлено — так и написать.
6. Если сканер ничего не нашёл — честно написать, что переменные и секреты не
   обнаружены.
7. Диаграмма не нужна.

### 4. Проход полноты

`internal static` метод `EnsureAllVariablesListed(content, scanResult, languageCode)`.

- Для каждого имени из сканера проверить, встречается ли оно в тексте страницы.
  Для ключа .NET годится любая из двух форм. Совпадение — целым словом,
  `Ordinal`.
- Отсутствующие дописать в конец разделом «Не описано при генерации» (`ru`) /
  `Not described during generation` (остальные языки; для `zh*` можно китайский)
  — таблица: имя, секрет?, места, «назначение не установлено».
- Если все на месте, текст не меняется.

Перегенерация одного документа из админки (`RegenerateDocumentAsync`) идёт через
тот же `GenerateDocumentContentAsync`, поэтому своё сообщение, бюджеты и проход
полноты срабатывают и там.

Вызывается в `GenerateDocumentContentAsync` после **успешной** генерации этой
страницы: прочитать `DocFile.Content`, прогнать, при изменении сохранить с
`UpdateTimestamp()`. Результат сканера для прохода — тот же, что пошёл в
сообщение. Повторно не сканировать.

## Чего не делать

- Не трогать файлы в `prompts/`, перевод, инкрементальное обновление, фронт, `docs/`.
- Не добавлять вычистку текста и запреты на `ReadFile`.
- Не менять формат оглавления и API.
- Не выводить значения секретов: ни в таблицу, ни в лог, ни в `ToString()` записи.

## Тесты (xUnit)

**Сканер** (фикстуры во временной папке):
- по фикстуре на каждый источник: имена, источники и места `path:line`;
- пропуск `node_modules`, `bin`, бинарного файла и файла больше 512 КБ;
- `AI:Endpoint` и `AI__Endpoint` дают одну запись;
- ловушки **не попадают** в выдачу:
  - `$${HOME}` и `${PWD}` в compose `command:`;
  - `- name: nginx` вне `env:`;
  - `environment: production` в workflow;
  - `GetSection("Logging")`;
  - `${X}` в `README.md` и `run.sh`;
- классификация:
  - секреты: `OPENAI_API_KEY`, `apiKey`, `ApiKey`, `DB_PASSWORD`,
    `ConnectionStrings:Default`, `secrets.DEPLOY`, `secretKeyRef`;
  - не секреты: `LOG_LEVEL`, `PORT`, `AUTHOR`, `AUTHORITY`, `CERT_PATH`,
    `TOKEN_TTL`, `KEY_VAULT_URL`, `PWD`;
- **значения секретов не выдаются нигде**. Параметризованно по источнику:
  `.env.example`, `.env`, `${API_KEY:-v}`, `ENV API_KEY=v` и compose
  `environment:`. Значение не встречается ни в `DefaultValue`, ни в отрисовке,
  ни в `ToString()`, ни в сообщениях подставного `ILogger`;
- `DefaultValue` не-секрета: из `.env.example` и `${X:-d}` берётся, из `.env` — нет;
- детерминизм: одни и те же файлы, созданные в двух временных каталогах в
  разном порядке, с путями в разном регистре и с кириллицей, дают одинаковую
  выдачу;
- объём: больше 24 000 символов — таблица обрезана, остальные имена перечислены
  строкой;
- пустой репозиторий — фраза «не обнаружены»;
- нечитаемый файл — пропуск без исключения.

**Обязательный пункт** (как в `CatalogStorageShrinkGuardTests`, на InMemory):
- пункта нет — добавлен последним верхнего уровня, `order` верный;
- заголовки для `ru`, `ZH`, `zh-tw`, `pt-br`;
- пункт уже есть, в том числе с другим регистром и слешами, — без изменений;
- двойной вызов не дублирует;
- до вставки к листу привязан `DocFile`, после вставки `Id` всех прежних записей
  и `DocFileId` листа те же;
- есть мягко удалённая запись с путём `environment-and-secrets`, как при второй
  полной генерации: после вызова пункт живой, без дубля;
- пункт есть с детьми — без изменений.

**Сообщение и бюджеты:**
- `IsEnvironmentPage`: `environment-and-secrets`, `/Environment-And-Secrets/` —
  да, `overview` — нет;
- `GetDocumentBudgets`: для этой страницы 12 и не меньше 20, для других —
  значения из опций;
- `BuildEnvironmentPageMessage` содержит таблицу сканера, File Reference Base
  URL и Runtime Context, и **не содержит** подстрок `at least one`
  (про диаграмму) и `at most {MaxDocumentSourceToolCalls} total calls`.

**Проход полноты:**
- страница без части имён — после прохода есть все, в разделе «Не описано…»;
- страница со всеми именами — текст не изменился;
- ключ .NET, упомянутый как `A__B`, засчитан;
- имя, входящее в другое слово (`PORT` внутри `REPORT`), не засчитано.

**Проводка в `WikiGenerator`**: если существующие тесты генератора (например
`WikiGeneratorDocumentFailureTests`) дают стенд с подставным агентом, добавить
тест, что для этой страницы ушло своё сообщение и после генерации выполнен
проход полноты. Если такого стенда нет — написать это в отчёте. Проводку я
проверю ручным прогоном.
