# 05. Обязательная страница «Переменные окружения и секреты» в каждой вики

## Зачем

Владелец хочет, чтобы в **каждой** сгенерированной вики была страница-справочник:
все переменные окружения и все ожидаемые секреты репозитория, и для каждой —
назначение и где используется.

Сейчас такой страницы может не быть: оглавление целиком придумывает LLM. Для
вики самого проекта она появилась (`deployment-operations.configuration`), для
`service-graph` — нет. Положиться на просьбу в промпте нельзя: локальная модель
её иногда пропустит.

Важно для безопасности: вики читается **без входа**, а владелец может
генерировать вики по коду банка. Значения секретов не должны попадать в текст ни
при каких условиях.

## Принятые решения (не пересматривать)

1. **Пункт гарантирует код, а не модель.** После того как модель записала
   оглавление, отдельный сервис добавляет пункт с фиксированным путём
   `environment-and-secrets`, если его нет.
2. **Полноту даёт детерминированный сканер, а не модель.** У агента на страницу
   всего `MaxDocumentSourceToolCalls = 6` обращений к файлам. Поэтому сканер по
   шаблонам сам находит имена переменных и места использования, а результат
   подмешивается в сообщение агенту. Модель только объясняет назначение.
3. **Значения секретов на страницу не пишутся.** Владелец подтвердил, что в его
   коде настоящих значений нет, только заглушки. Поэтому детерминированной
   вычистки текста нет. Сканер не отдаёт значений переменных, похожих на секреты,
   а инструкция запрещает модели их писать.
4. **Минимальный след в апстримном коде.** Всё новое — в новых файлах. В
   `WikiGenerator.cs` допускаются:
   - вызов сервиса обязательного пункта в `GenerateCatalogAsync`;
   - одна ветка `if` в `GenerateDocumentContentAsync` для этого пути: добавить
     инструкции к сообщению;
   - если понадобится — увеличенный бюджет инструментов для этого пути.
5. **Общий промпт `content-generator.md` и промпт оглавления не трогать.**
   Инструкции для страницы живут в новом файле промпта или в коде нового класса.

## Что сделать

### 1. Обязательный пункт оглавления

Новый сервис, например `MandatoryCatalogPages`, с методом, который вызывается в
`WikiGenerator.GenerateCatalogAsync` сразу после проверки
`catalogItemCount == 0`, до логов об успехе.

- Читает оглавление через `CatalogStorage.GetCatalogJsonAsync`. Если ни на одном
  уровне нет пункта с путём `environment-and-secrets`, добавляет его
  **последним пунктом верхнего уровня**: `order` на единицу больше максимального,
  без детей. Записывает через `CatalogStorage.SetCatalogAsync`.
- Перед реализацией проверить, что `SetCatalogAsync` в этот момент (документов
  ещё нет) ничего не теряет: связи с `DocFile`, `Id` существующих пунктов. В
  отчёте написать, что проверено.
- Заголовок по языку ветки:

  | код | заголовок |
  |---|---|
  | `ru` | `Переменные окружения и секреты` |
  | `en` | `Environment variables and secrets` |
  | `zh` | `环境变量与密钥` |
  | остальные | английский |

- Идемпотентность: повторный вызов пункт не дублирует.

Уже существующие вики пункт получат при следующей полной генерации или
перегенерации из админки. Отдельной миграции не делать.

### 2. Сканер `EnvironmentReferenceScanner`

Чистый детерминированный класс, на вход — путь к рабочей копии репозитория.

**Обход:**
- пропускать каталоги `.git`, `node_modules`, `bin`, `obj`, `dist`, `build`,
  `out`, `target`, `vendor`, `.venv`, `venv`, `__pycache__`, `.next`, `coverage`;
- пропускать файлы больше 512 КБ и бинарные (в первых 8 КБ есть нулевой байт);
- порядок обхода и выдачи детерминированный: по пути, затем по строке.

**Что ищется.** Имя переменной — по `^[A-Za-z_][A-Za-z0-9_]*$`, ключ
конфигурации .NET — с `:` (`AI:Endpoint`).

| Источник | Шаблоны |
|---|---|
| C# | `Environment.GetEnvironmentVariable("X")`, `configuration["X"]` / `_configuration["X"]` / `config["X"]`, `GetValue<…>("X")`, `GetSection("X")` |
| Python | `os.getenv("X")`, `os.environ["X"]`, `os.environ.get("X")`, `environ.get("X")` |
| JS/TS | `process.env.X`, `process.env["X"]`, `import.meta.env.X` |
| Go | `os.Getenv("X")`, `os.LookupEnv("X")` |
| Java/Kotlin | `System.getenv("X")`, `${X}` и `${X:default}` в `application*.yml` / `application*.properties`, `@Value("${x}")` |
| Docker/compose | `${X}`, `${X:-d}`, `${X-d}` в `docker-compose*.yml` / `compose*.yaml` / `compose*.yml`; ключи в `environment:` (список `- X=…` и словарь `X: …`); `ENV X` и `ARG X` в `Dockerfile*` |
| Kubernetes/Helm | `env:` → `- name: X` в YAML; `secretKeyRef` (имя переменной из `name`) |
| CI | `${{ secrets.X }}`, `${{ vars.X }}` в `.github/workflows/*.yml` |
| Примеры | ключи `X=` в `.env.example`, `.env.sample`, `.env.template`, `*.env.example` |

Ключ .NET вида `A:B` дополнительно показывать в форме переменной окружения
`A__B`. Одна запись на имя: формы `A:B` и `A__B` объединяются.

**Выход — запись на каждое имя:**
- `Name` (и `EnvName`, если отличается);
- `Sources` — множество источников из таблицы;
- `Locations` — до 5 мест `path:line` (путь относительно корня, прямые слеши);
- `IsLikelySecret` и `SecretReason`. Секретом считается имя, где встречается
  (без учёта регистра) `KEY`, `SECRET`, `TOKEN`, `PASSWORD`, `PASSWD`, `PWD`,
  `CREDENTIAL`, `PRIVATE`, `CERT`, `DSN`, `CONNECTION_STRING`,
  `CONNECTIONSTRING`, `AUTH`, а также пришедшее из `secrets.X` или `secretKeyRef`;
- `DefaultValue` — **только** для не-секретов и **только** из `.env.example` /
  `.env.sample` / `.env.template` / `${X:-d}` / `${X:d}` / `ENV X=d`. Из настоящих
  `.env` и из кода значения не брать. Для секретов `DefaultValue` всегда `null`.

**Отрисовка** для промпта: метод, который превращает результат в markdown-таблицу
(имя, секрет?, источники, по умолчанию, места) с ограничением объёма. Больше
150 переменных — показать первые 150 по имени и строку «…и ещё N».

### 3. Инструкции для страницы

В `GenerateDocumentContentAsync`, если путь равен `environment-and-secrets`,
к пользовательскому сообщению добавляется блок: результат сканера и
требования к странице. Требования вынести в новый файл промпта
(`prompts/env-secrets-page.md`, загрузка через тот же `_promptPlugin`) или в
константу нового класса.

**Требования к странице** (на языке ветки):
1. H1 — заголовок пункта.
2. Короткое вступление: откуда приложение берёт настройки (env, `.env`,
   compose, k8s, CI), на основе найденных источников.
3. **Таблица переменных окружения** (не-секретов): имя, назначение,
   обязательна ли, значение по умолчанию, где используется (ссылки на файлы
   по File Reference Base URL).
4. **Таблица секретов**: имя, что это (API-ключ к X, пароль БД Y…), откуда
   ожидается (k8s Secret, CI secret, `.env`), где используется.
   **Значения не писать никогда**, даже если они встретились в файлах; вместо
   примера значения — `***`.
5. Каждая строка обеих таблиц опирается на место из сканера или на прочитанный
   файл. Переменные из сканера не выбрасывать. Если назначение не удалось
   установить, так и написать: «назначение не установлено» и место.
6. Если сканер ничего не нашёл — страница всё равно создаётся и честно говорит,
   что переменные окружения и секреты в репозитории не обнаружены.
7. Mermaid-диаграмма для этой страницы **не обязательна**. Явно отменить общее
   требование «at least one diagram» в добавляемом блоке.

Бюджет инструментов для этой страницы — 12 обращений вместо 6. Найти, где
создаётся бюджет документа, и сделать исключение для этого пути.

## Чего не делать

- Не трогать `content-generator.md`, `catalog-generator.md`,
  `incremental-updater.md`, переводы, фронт, `docs/`.
- Не менять формат оглавления и API.
- Не отдавать значения секретов ни из сканера, ни в логи, ни в тестовые
  сообщения об ошибках.

## Тесты (xUnit)

**Сканер** — фикстуры во временной папке:
- по файлу на каждый источник из таблицы: правильные имена, источники и места
  `path:line`;
- пропуск `node_modules`, `bin`, бинарного файла и файла больше 512 КБ;
- `AI:Endpoint` и `AI__Endpoint` — одна запись;
- классификация: `OPENAI_API_KEY`, `DB_PASSWORD`, `secrets.DEPLOY` и
  `secretKeyRef` — секреты; `LOG_LEVEL` и `PORT` — нет;
- **значения секретов не выдаются никогда**: `.env.example` с
  `OPENAI_API_KEY=sk-real-1234567890`, у записи `DefaultValue == null`, и строка
  `sk-real-1234567890` не встречается в отрисованной таблице;
- `DefaultValue` не-секрета берётся из `.env.example` и `${X:-d}`, но не из `.env`;
- порядок выдачи детерминированный (два прогона дают одно и то же);
- больше 150 переменных — обрезка со строкой «…и ещё N».

**Обязательный пункт** (на SQLite или как принято в тестах `CatalogStorage`):
- пункта нет — добавлен последним верхнего уровня с правильным `order` и
  заголовком для `ru`, `en`, `zh` и неизвестного языка;
- пункт уже есть на любом уровне — ничего не меняется;
- двойной вызов не дублирует;
- существующие пункты после вставки на месте: те же пути, заголовки, порядок,
  дети.

**Инструкции:**
- блок добавляется только для пути `environment-and-secrets`;
- в блоке есть таблица сканера и отмена требования диаграммы.

Вынести сборку сообщения в тестируемый метод.
